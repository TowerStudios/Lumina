## BUG 修复（2026-08-04 会话）

用户测试反馈 3 个 BUG，已全部修复：

### 1. 群聊消息从最早开始展示
- **根因**：chatStore.loadMessages 调用 `getMessages(..., ascending=true)`，游标从最旧消息开始。后端设计契约是 `offset=0 + ascending=false` = 最新一批（chatService.ts:2482 有缓存最新批次的逻辑）。
- **修复**：loadMessages/loadMoreMessages 均改 ascending=false；新增 `nextOffsetBySession` 状态，用后端返回的 nextOffset 分页（原来错误传 messages.length 导致游标反复重建）；loadMore 前插前按 id 去重。

### 2. 下拉加载历史时闪退（加载循环）
- **根因**：`.chat-view__messages` 设置了 `scroll-behavior: smooth`。加载更多后 `container.scrollTop = diff` 触发 smooth 动画，动画期间持续触发 scroll 事件 → scrollTop<50 反复成立 → 加载更多循环（日志证实 67ms 内连续 2 次 getMessages）→ UI 卡死。
- **修复**：移除容器 smooth；加载更多加 600ms 冷却（loadMoreCooldownRef）；滚动恢复改即时定位。

### 3. 群聊头像、成员数量不对
- **根因**：adaptSession 的 memberCount 恒为 undefined（后端 getSessions 不返回）；loadSessions 用 getContactAvatar 给群聊填充了不可靠的个人头像。
- **修复**：
  - 新增 IPC `chat:getGroupMemberCounts`（wcdbService.getGroupMemberCounts）+ `chat:getGroupAvatar`（前 4 个成员头像 URL）
  - chatStore：loadSessions 跳过群聊的头像填充；新增 loadGroupMeta（批量成员数）+ loadGroupAvatar（合成头像 map）
  - ChatView：新增 GroupCompositeAvatar 组件（2x2 成员头像合成，TG 风格）；header 成员数显示真实值（无值时显示"群聊"而非"0 名成员"）

### 附加：TG 风格"快速到底"按钮
- ChatView 新增 showJumpToBottom 状态（远离底部 120px 时显示），点击 scrollTo({top, behavior:'smooth'})；首屏加载完成后即时 scrollIntoView 到底部。

### 关键教训
- **Electron 渲染层滚动容器不要用 CSS scroll-behavior: smooth**（除非配合节流/冷却），否则加载更多场景会形成事件风暴。
- 用户测试时运行的是旧构建（日志显示 "No handler registered for 'emoji:get'"），部分问题源于构建过期，重新构建即可。
