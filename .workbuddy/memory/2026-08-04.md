## 重启 Lumina 的关键环境坑（重要！）

**问题**：从 agent 的 Bash shell 用 `npm run dev` 启动 Lumina 时，Electron 主进程崩溃：
```
electron.app.setName("Lumina");
TypeError: Cannot read properties of undefined (reading 'setName')
Node.js v24.18.0
```

**根因**：沙箱环境强制设置了 `ELECTRON_RUN_AS_NODE=1`（env 里 `echo $ELECTRON_RUN_AS_NODE` = `1`）。
该变量会让 Electron 退化成纯 node 运行：
- `process.type` = `undefined`（正常应为 `browser`）
- `require('electron')` 返回二进制路径字符串（Object.keys 是字符下标 0,1,2...），不是 API 对象 → `electron.app` 为 undefined
- 不会打开 GUI 窗口

**诊断方法**：
```
env | grep ELECTRON_RUN_AS_NODE   # 确认变量存在
# 对比测试：
node_modules/electron/dist/electron.exe .e-test.js   # 崩溃
env -u ELECTRON_RUN_AS_NODE node_modules/electron/dist/electron.exe .e-test.js  # process.type=browser, 正常
```

**正确重启方式**（去掉该变量）：
```
cd G:/Lumina-main
env -u ELECTRON_RUN_AS_NODE npm run dev
```
- vite-plugin-electron 会按 `electron/path.txt`（值为 `weflow.exe`）spawn 二进制，启动主进程 + 渲染窗口
- 启动后进程名为 `weflow.exe`（不是 electron.exe），用 `tasklist | grep weflow` 确认
- 应用日志：`C:/Users/Administrator/AppData/Roaming/Lumina/logs/main-YYYY-MM-DD.log`

**附带发现**：
- `node_modules/electron/index.js` 无条件 `module.exports = getElectronPath()`（返回二进制路径），无 `process.versions.electron` 守卫——这是 npm 包的"工具版"，正常情况下由 Electron 运行时拦截 `require('electron')` 返回真正 API；仅在 run-as-node 时才暴露路径字符串。
- 用 Git Bash 时 `taskkill` 要用单斜杠（`taskkill /F /PID xxx`），`//F` 会被当路径报错；`sleep`/`seq` 命令不存在，用 `node -e "busywait"` 替代。
- 清理残留：之前 `npm run dev` 失败会留下挂起的 vite node 进程（占 3000 端口）+ electron 测试进程，重启前先 taskkill 掉。
